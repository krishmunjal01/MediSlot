Source Implementation:

String sql = "SELECT * FROM patients WHERE patient_id = ?";
try (Connection conn = dataSource.getConnection();
     PreparedStatement ps = conn.prepareStatement(sql)) {
    ps.setLong(1, patientId);
    try (ResultSet rs = ps.executeQuery()) {
        if (rs.next()) {
            return Optional.of(mapResultSetToPatient(rs));
        }
    }
} catch (SQLException e) {
    throw new RuntimeException(e);
}

Source Implementation:

String sql = "SELECT * FROM patients WHERE patient_id = ?";
try {
    Patient patient = jdbcTemplate.queryForObject(
        sql, 
        patientRowMapper, 
        patientId
    );
    return Optional.ofNullable(patient);
} catch (EmptyResultDataAccessException e) {
    return Optional.empty();
}

Technical Comparison Matrix (Evaluation Defense)

Evaluation Dimension Traditional JDBC Spring JdbcTemplate
Connection Acquisition Explicit via dataSource.getConnection() or DriverManager Automatic via Spring-configured HikariCP DataSource
Boilerplate Code High (~15 lines per query for try/catch/resources) Minimal (1 declarative method call)
Parameter Binding Manual 1-based index (ps.setString(1, val)) Varargs / Prepared parameter array
ResultSet Extraction Manual cursor loop (rs.next(), rs.getString()) Clean functional abstraction via RowMapper<T>
Exception Hierarchy Checked java.sql.SQLException requires manual handling Unchecked DataAccessException hierarchy translated by Spring
Transaction Management Manual conn.setAutoCommit(false) and conn.commit() Declarative Spring @Transactional integration
